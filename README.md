# Интеллектуальный тренажёр для подготовки к собеседованиям

Веб-приложение, которое имитирует техническое собеседование и даёт развёрнутую
обратную связь по каждому ответу. Тренажёр задаёт вопросы по выбранному направлению
и уровню, оценивает ответы с помощью ИИ по четырём критериям, объясняет ошибки,
показывает эталонный ответ, ведёт чат-консультацию по теории, проверяет решения
задач по коду и собирает аналитику прогресса.

Проект состоит из двух частей: REST API на FastAPI и SPA на React + TypeScript.
После сборки фронтенда всё приложение раздаётся одним процессом `uvicorn`
(собранный бандл лежит в `backend/app/static`). Данные хранятся в SQLite,
аутентификация — JWT.

ИИ-слой спроектирован с двумя движками: **Live** (любой OpenAI-совместимый API —
OpenAI, OpenRouter, DeepSeek, **Google Gemini**, локальная Ollama) и **Offline**
(детерминированный локальный движок на встроенном банке вопросов и эвристиках).
При отсутствии ключа или ошибке внешней модели сервис автоматически переключается
на офлайн-движок, поэтому полный сценарий тренировки работает без интернета и без
оплаты API.

```text
┌────────────────────┐   JSON / SSE    ┌──────────────────────────────────────────────┐
│  SPA (React + TS)  │────────────────►│ FastAPI: /api/auth, /api/interviews,         │
│  дашборд, сессия,  │◄────────────────│ /api/chat, /api/code, /api/analytics, …      │
│  чат, код, профиль │                 │                                              │
└────────────────────┘                 │  ┌────────────────────────────────────────┐  │
                                       │  │ ИИ-слой (AIService + fallback)         │  │
                                       │  │ Live    ──► внешняя LLM (опционально)  │  │
                                       │  │ Offline ──► банк вопросов и эвристики  │  │
                                       │  └────────────────────────────────────────┘  │
                                       │  SQLAlchemy ──► SQLite backend/data/app.db   │
                                       └──────────────────────────────────────────────┘
```

## Возможности

| Блок | Что делает пользователь | Как это реализовано |
|---|---|---|
| Аутентификация | Регистрация и вход по email/паролю | `POST /api/auth/register`, `POST /api/auth/login`, JWT (HS256) на 7 дней, пароли — PBKDF2-SHA256 |
| Профиль | Указывает направление подготовки и уровень, добавляет текст резюме | `GET/PUT /api/profile`; резюме учитывается при генерации вопросов |
| Собеседование | Выбирает роль (backend, frontend, QA, аналитика, DevOps, HR), уровень (intern…senior), режим (теория / смешанный / с кодом) и число вопросов | `POST /api/interviews`; вопросы генерирует ИИ, при сбое — встроенный банк |
| Ответы и ИИ-оценка | Отвечает текстом (в UI — в том числе голосом через Web Speech API), получает балл 0–10 по критериям `correctness`, `completeness`, `depth`, `clarity`, список сильных сторон и пробелов, эталонный ответ и рекомендацию | `POST /api/interviews/{id}/answers` |
| Адаптивность | Запрашивает дополнительный вопрос по слабым темам | `POST /api/interviews/{id}/questions/next` (до 30 вопросов в сессии) |
| Итоговый отчёт | Завершает сессию и получает сводный вердикт, оценки по темам и рекомендации | `POST /api/interviews/{id}/finish` |
| История | Смотрит, фильтрует и удаляет прошлые сессии | `GET /api/interviews`, `GET /api/interviews/{id}`, `DELETE /api/interviews/{id}` |
| Чат по теории | Задаёт вопросы ассистенту, получает потоковый (SSE) ответ, создаёт и удаляет диалоги | `/api/chat/conversations…` |
| Код-ревью | Генерирует задачу по теме/языку/сложности, отправляет решение и получает ревью без исполнения кода: оценку, замечания (`critical`/`major`/`minor`/`nit`), улучшенный вариант, оценку сложности | `POST /api/code/tasks`, `POST /api/code/tasks/{id}/review`, `GET /api/code/history` |
| Аналитика | Видит количество сессий, средний и лучший балл, число отвеченных вопросов, стрик, слабые/сильные темы, динамику оценок | `GET /api/analytics/overview` |
| Состояние ИИ | Видит в интерфейсе, какой движок активен — `live` или `offline` | `GET /api/ai/health`; сводка также в `GET /api/health` |
| Распознавание речи | Говорит вместо набора ответа | В интерфейсе — Web Speech API браузера (`ru-RU`) с аккуратным fallback; для интеграций доступен серверный `POST /api/voice/transcribe` (Whisper через OpenAI-совместимый провайдер, `503` при недоступности) |

Направления и темы задаются справочником (`backend/app/data/catalog.py`),
контент — встроенным банком (`backend/app/data/question_bank.py`: 163 вопроса
и 18 задач по коду, 39 тем по шести направлениям). Банк используется и
ИИ-слоем, и офлайн-движком, поэтому тренировка работает без ключей API.

## Интерфейс

Дизайн — рабочий инструмент, а не промо-страница: плотные таблицы, один акцентный
цвет, нейтральная база. Полное описание — [docs/06-Дизайн-система.md](docs/06-Дизайн-система.md).

* **Светлая тема по умолчанию**, переключатель light/dark/system в сайдбаре и меню
  пользователя (выбор сохраняется); тёмная тема приглушённая, без неона.
* **Каркас:** боковая навигация 240px (на планшете — 64px с иконками, на телефоне —
  выдвижное меню), верхняя панель 56px с хлебными крошками.
* **Глобальный поиск** (`Ctrl/⌘ + K`) с автодополнением по сессиям и диалогам,
  управление стрелками/Enter/Esc.
* **Фильтры и табы:** направления, уровень, диапазон баллов, «Сбросить» в истории;
  табы «Обзор / Сессии / Темы» на дашборде, «Задача / История» в код-ревью.
* **Уведомления:** фактический режим ИИ, измеренная задержка, завершённые сессии,
  «прочитать всё».
* **Состояния и доступность:** skeleton/empty/error, disabled во время запросов,
  видимый фокус (`focus-visible`), aria-атрибуты, кликабельные зоны ≥ 40×40px,
  контраст по WCAG 2.1 AA.
* **Адаптивность:** 12-колоночная сетка на десктопе (контейнер 1200px), две колонки
  на планшете, одна колонка и sticky-кнопки на мобильном.

## Сколько это стоит

Проект полностью бесплатен: все используемые библиотеки — открытый исходный код,
платных сервисов и подписок нет.

| Компонент | Стоимость | Комментарий |
|---|---|---|
| Код проекта, FastAPI, React, SQLite | **0 ₽** | Открытый исходный код, запуск на своём компьютере |
| Встроенный офлайн-ИИ (банк вопросов + эвристики) | **0 ₽** | Без ключа, без интернета, без регистраций |
| Gemini API в live-режиме | **0 ₽** в рамках бесплатного тарифа | Ключ из Google AI Studio; платный тариф не нужен |
| Ollama (локальная LLM) | **0 ₽** | Полностью офлайн, нужен ПК с 8+ ГБ RAM |
| Хостинг | **0 ₽** | Не требуется: приложение запускается локально |

Бесплатный тариф Gemini даёт доступ к части моделей (как правило, класс Flash /
Flash-Lite) с лимитами на количество запросов в минуту и в сутки. Флагманские
модели (например, Gemini 4 Argon) в бесплатный тариф **не входят** — их
использовать не обязательно. Актуальные лимиты и состав моделей видны в
[AI Studio → Rate limits](https://aistudio.google.com/rate-limit).

Если квота исчерпана (ошибка `429`) или ключ/модель недоступны, приложение
автоматически переключается на встроенный офлайн-движок: пользователь продолжает
заниматься, и это ничего не стоит. Для 100 % гарантии бесплатности и независимости
от сети используйте `AI_PROVIDER=offline` (или просто оставьте `AI_API_KEY` пустым).

> На бесплатном тарифе Google может использовать содержимое запросов для улучшения
> своих сервисов — это условие тарифа. Для учебного проекта это не критично;
> на платном тарифе такие данные не используются.

Минимально достаточно оставить `AI_API_KEY` пустым — приложение запустится в

#### Подключение Gemini (если нет доступа к OpenAI)

У Google есть официальный OpenAI-совместимый шлюз, поэтому Gemini подключается
без изменения кода.

1. Получите ключ в [Google AI Studio](https://aistudio.google.com/apikey)
   (Create API key; ключ начинается на `AIza...`).
2. Откройте файл **`backend/.env`** и вставьте ключ в строку `AI_API_KEY=`:

   ```ini
   AI_PROVIDER=gemini
   AI_API_KEY=AIza...ваш_ключ...
   AI_MODEL=gemini-3.5-flash-lite
   ```

   Ничего больше менять не нужно: адрес шлюза
   (`https://generativelanguage.googleapis.com/v1beta/openai`) подставляется
   автоматически. Если в вашем аккаунте доступна другая модель — укажите её
   идентификатор в `AI_MODEL`.
3. Перезапустите приложение и проверьте режим:

   ```powershell
   .\scripts\start.ps1
   Invoke-RestMethod http://127.0.0.1:8000/api/ai/health
   ```

   Ожидается `"mode": "live"`. Бейдж `live`/`offline` также виден в интерфейсе на
   странице «Профиль». Если ключ неверный или сеть недоступна, приложение
   автоматически вернётся в офлайн-режим и продолжит работать.

Эквивалентная запись «вручную» через OpenAI-режим (если хочется явно задать шлюз):

```ini
AI_PROVIDER=openai
AI_API_KEY=AIza...
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
AI_MODEL=gemini-3.5-flash-lite
```

Остальные варианты (OpenAI, OpenRouter, DeepSeek, локальная Ollama) — в
комментариях `backend/.env.example`.

#### Скорость и задержки ИИ

Каждое действие (создать собеседование, проверить ответ, отчёт, код-ревью) — это
один запрос к модели, поэтому задержка зависит от модели и лимитов тарифа.

Что сделано в проекте для скорости:

* по умолчанию для Gemini выбрана быстрая `gemini-3.5-flash-lite` (замеры ниже);
* таймаут 45 с и один повтор (`AI_TIMEOUT_SEC`, `AI_MAX_RETRIES`) вместо долгого ожидания;
* при исчерпанной квоте (`429`) запросы **не повторяются** — сразу офлайн-режим;
* «предохранитель» (`AI_FAILURE_COOLDOWN_SEC=120`): после сбоя живого ИИ следующие
  запросы выполняются офлайн мгновенно, без ожидания; через 2 минуты приложение
  снова попробует живую модель;
* health-проверка кэшируется на 5 минут, а в чате используется потоковый ответ.

Замеры на реальном ключе Gemini (Flash-Lite):

| Операция | Время |
|---|---|
| health-проверка | ~0,5 с |
| генерация 3 вопросов | 3–4 с |
| оценка ответа (4 критерия + эталон) | ~2 с |
| итоговый отчёт | 1–2 с |
| код-задача / код-ревью | 1–2 с |
| чат: первый токен / весь ответ | 0,5 / 1,5 с |
| любая операция в офлайн-режиме | < 0,05 с |

Проверить у себя: `& ".venv\Scripts\python.exe" tools\ai_benchmark.py`.

Если всё равно медленно:

* на бесплатном тарифе возможен троттлинг — отдельные запросы иногда занимают
  5–20 с; это ограничение Google, а не проекта;
* `gemini-3.6-flash` и `gemini-3.8-flash` дают лучшее качество, но медленнее и
  могут быть недоступны на free tier (вернут `429`);
* при ошибке квоты приложение автоматически переключается в офлайн-режим и
  продолжает работать без задержек.

### 3. Сборка фронтенда

```powershell
Set-Location "$ws\frontend"
npm install
npm run build
```

`frontend/vite.config.ts` настроен так, что результат сборки попадает в
`backend/app/static` (`emptyOutDir: true`). После этого SPA и API раздаются
одним сервером. Особенности установки и сборки в ограниченной песочнице Windows
(флаги `npm install`, Vite 8) описаны в [frontend/README.md](frontend/README.md)
и [docs/DEV_SETUP.md](docs/DEV_SETUP.md).

### 4. Запуск

```powershell
$ws = "C:\Users\MILLER\Downloads\HH7d"
Set-Location "$ws\backend"
& "$ws\.venv\Scripts\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8000/ | Приложение (SPA) |
| http://127.0.0.1:8000/api/health | Проверка работоспособности, режим ИИ |
| http://127.0.0.1:8000/api/docs | Swagger UI (OpenAPI) |

Для разработки фронтенда отдельно: `npm run dev` в `frontend/` — Vite-сервер
на `http://127.0.0.1:5173` с проксированием `/api` на `http://127.0.0.1:8000`.

## Режимы ИИ

| `AI_PROVIDER` | Поведение |
|---|---|
| `auto` (по умолчанию) | Если задан `AI_API_KEY` — Live-движок, иначе Offline-движок |
| `gemini` | Google Gemini через OpenAI-совместимый шлюз: нужен только `AI_API_KEY` |
| `openai` | Любой OpenAI-совместимый API: OpenAI, OpenRouter, DeepSeek, VseGPT, Gemini и др. |
| `ollama` | Локальная модель через Ollama (`http://localhost:11434/v1`), без ключа |
| `offline` | Принудительно встроенный офлайн-движок (демонстрация без ключа и сети) |

Даже при активном Live-движке любой сбой внешней модели (таймаут, ошибка HTTP,
невалидный JSON) приводит к прозрачному переключению на офлайн-движок — пользователь
получает ответ в любом случае. Текущий режим виден в интерфейсе и в `GET /api/ai/health`.
