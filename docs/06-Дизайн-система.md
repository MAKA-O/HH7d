# 06. Дизайн-система «Тренажёр собеседований»

Версия: **1.0** (редизайн после первой итерации).
Область: SPA в `frontend/`, все 11 экранов. API-контракт (`docs/API.md`) не менялся.
Цель документа: зафиксировать визуальный язык, токены, сетку, анатомию экранов и правила
доступности так, чтобы новые страницы и компоненты собирались без «дизайна на глаз».

## 1. Принципы

1. **Продукт, а не промо-страница.** Интерфейс ближе к рабочему инструменту (Linear, Stripe
   Dashboard, GitHub): плотные списки, таблицы, предсказуемые контролы. Никаких маркетинговых
   hero-блоков, отзывов и «вау»-эффектов.
2. **Один акцент.** Синий `#2563eb` отвечает за главное действие, активное состояние и ссылки.
   Красный/зелёный/жёлтый — только семантика (опасность/успех/внимание), не декор.
3. **Нейтральная база.** Белый и серый slate; тёмная тема — приглушённая, без неона и свечения.
4. **Честность данных.** В интерфейсе нет выдуманных цифр, рейтингов и обещаний. Режим ИИ
   (`live`/`offline`) и измеренная задержка показываются как есть; пустые состояния объясняют,
   что появится после первых действий.
5. **Плотность с воздухом.** Строки таблиц 44px, контролы 40px, отступы кратны 8px; при этом
   секции разделены 16–24px, чтобы плотность не превращалась в кашу.
6. **Доступность по умолчанию.** Фокус видим всегда, кликабельные зоны не меньше 40×40px,
   контраст текста ≥ 4.5:1, состояния не передаются только цветом.

## 2. Токены

Токены живут в двух местах:

* `frontend/tailwind.config.js` — имена цветов/шрифтов/теней (`bg-surface`, `text-fg-2`, …);
* `frontend/src/index.css` — значения CSS-переменных для светлой (`:root`) и тёмной (`.dark`) тем.

Цвета заданы в RGB-каналах (`--canvas: 247 248 250`), поэтому работают модификаторы прозрачности
Tailwind: `bg-accent/10`, `border-negative/25`.

  с прозрачностью ≤ 8%;
* статус нельзя передавать только цветом: у бейджа всегда есть текст, у ошибки — иконка и текст.

### 2.2. Типографика

Шрифт: `Inter`, далее `system-ui` (без внешней загрузки — работает офлайн).
Базовая плотность: **body 14px / line-height 20px**.

| Класс | Размер / интерлиньяж | Начертание | Применение |
|---|---|---|---|
| `text-12` | 12 / 16 | 400–500 | метаданные, подписи бейджей, хлебные крошки на мобильном |
| `text-13` | 13 / 18 | 400–500 | вторичный текст, описания в карточках, таблицы, кнопки small |
| `text-14` | 14 / 20 | 400–600 | базовый текст, кнопки, поля ввода, заголовки карточек |
| `text-16` | 16 / 24 | 400–600 | вопрос собеседования, крупные значения |
| `text-20` | 20 / 28 | 600 | заголовок страницы (мобильный), модальный заголовок |
| `text-24` | 24 / 32 | 600 | H1 страницы (десктоп), KPI-значения, «404» |
| `text-30` | 30 / 36 | 600 | крупные числа (страница 404, отдельные акценты) |

Дополнительно: `eyebrow` — 12px uppercase с трекингом `0.06em` для надзаголовков секций.
Заголовки всегда выровнены по левому краю; центрирование — только для пустых состояний и 404.

### 2.3. Отступы (сетка 8px)

Шкала: `4, 8, 12, 16, 24, 32, 40, 48, 64`.
Правила:

* внутренние отступы карточек: 16px (`p-4`) у компактных и 20px (`p-5`) у контентных;
* между карточками в колонке: 16px (`gap-4`), между секциями: 24px (`space-y-6` / `mt-6`);
* горизонтальные отступы контейнера: 16px на мобильном, 24px на планшете/десктопе (`px-4 sm:px-6`);
* вертикальные отступы страницы: 24px (`py-6`);
* таблицы: ячейки `px-4`, строка 44px; шапка 40px.

### 2.4. Радиусы, границы, тени

| Элемент | Радиус | Обоснование |
|---|---|---|
| Карточки, модалки, поповеры, таблицы | **8px** (`rounded-lg`) | основной контейнер |
| Кнопки, поля, сегменты, иконки-кнопки | **6px** (`rounded-md`) | компактные контролы |
| Бейджи, чипы, аватары | **999px** (`rounded-full`) | статусы и «пилюли» |
| Внутренние плашки (код, бейдж-ряды) | 6–8px | вложенность на один шаг не больше |

Границы: 1px `line`; интерактивные контролы при hover — `line-strong`; фокус — 2px `accent` с
отступом 2px. Тени: только две — `shadow-card` (`0 1px 2px rgba(15,23,42,.06)`) и `shadow-pop`
(для выпадающих панелей и модалок). Тени не используются как декор.

### 2.5. Иконки

`lucide-react`, размеры 16 / 18 / 20px (`h-4`, `h-[18px]`, `h-5`), толщина штриха — 1.75
(глобальное правило `.lucide { stroke-width: 1.75 }`). Иконка всегда сопровождает текст
(кроме кнопок с `aria-label`). Эмодзи в интерфейсе не используются.

### 2.6. Движение

Только функциональные переходы: цвет/границы — 150ms, прогресс-бары — 500ms, появление панелей —
150–200ms. Пульсация допустима лишь для индикатора загрузки/печати. Свечения и parallax нет.

## 3. Сетка и layout

### 3.1. Каркас

* **Десктоп ≥1280px:** сайдбар **240px** + контент; топбар **56px**; контейнер `max-w-[1200px]`
  с `px-6`; 12-колоночная сетка (`grid-cols-12`, `gap-4`).
* **Планшет 768–1279px:** сайдбар **64px**, только иконки (подписи — `sr-only`, заголовки в
  `title`); сетка 12 колонок сохраняется, но контентные блоки перестраиваются в 2 колонки.
* **Мобильный <768px:** сайдбара нет, навигация — drawer по гамбургеру; одна колонка;
  таблицы превращаются в карточки; на экране собеседования — sticky-панель действия снизу.

### 3.2. Сайдбар

Сверху бренд (знак 32×32 + название), затем навигация (высота пункта 40px, активный —
`bg-accent-soft`, текст `accent`). Внизу — статус ИИ (точка + «ИИ в сети · 240 мс» / «ИИ: офлайн»)
и кнопка переключения темы. На планшете остаются только иконки, статус ИИ — точка с `title`.

Пункты: **Дашборд**, **Новое собеседование**, **История сессий**, **Чат по теории**,
**Задачи с кодом**, **Профиль**.

иконка уведомлений, меню пользователя. На мобильном слева гамбургер, поиск открывается
полноэкранной панелью.

### 4.2. Единые состояния контролов

* **Default** — `border-line`, `bg-surface`.
* **Hover** — `border-line-strong` или `bg-surface-2` (для ghost).
* **Active/pressed** — фон темнее (`accent-hover`, `surface-2`).
* **Focus-visible** — `outline: 2px solid var(--accent); outline-offset: 2px`; у полей — ещё
  мягкое кольцо `box-shadow: 0 0 0 3px rgb(var(--accent)/.16)`.
* **Disabled** — `opacity: .5`, `cursor: not-allowed`; во время запроса кнопка получает
  `loading` (спиннер, повторное нажатие игнорируется).
* **Error** — `aria-invalid="true"`, рамка `negative`, текст ошибки под полем.

## 5. Паттерны

### 5.1. Глобальный поиск (автокомплит)

* Открывается по клику, Ctrl/Cmd+K или иконке на мобильном.
* Источники: `GET /api/interviews` (20 последних) и `GET /api/chat/conversations`; данные
  кешируются на 60 секунд, фильтрация — на клиенте (номер, роль, уровень, статус, дата, название
  диалога).
* Клавиатура: ↑/↓ — выбор, Enter — переход, Esc — закрытие; активный пункт подсвечен
  `bg-surface-2`; совпадение подчёркнуто `mark.search-mark`.
* Пустой результат: «Ничего не найдено. Попробуйте “PostgreSQL”, “backend” или номер сессии».
* Переход в диалог передаёт `state.conversationId`, страница чата сразу открывает нужный диалог.

### 5.2. Уведомления

Дропдаун колокольчика собирает:

1. статус ИИ из `GET /api/ai/health` (live/offline, провайдер, модель, измеренная задержка);
2. завершённые сессии из `GET /api/interviews` (последние 3, балл и направление);
3. ошибку, если `/api/ai/health` недоступен.

Непрочитанные помечены точкой; «Прочитать все» и прочтение по клику сохраняются в
`localStorage["iq-notifications-read"]` (массив id, обрезка до 100). Кнопка «Состояние ИИ и
настройки» ведёт в профиль.

### 5.3. Тема

Светлая по умолчанию. Режимы: `light`, `dark`, `system`; выбор хранится в
`localStorage["iq-theme"]`, применяется до первой отрисовки inline-скриптом в `index.html`
(нет «вспышки»). Класс `.dark` на `<html>`, токены меняются через CSS-переменные, поэтому
компоненты не содержат `dark:`-дублей (кроме одного pills-сегмента).

### 5.4. Данные и обратная связь

* Загрузка — skeleton той же формы, что и контент (карточки, строки таблицы).
* Ошибка — карточка с иконкой, текстом `detail` и кнопкой «Повторить».
* Пусто — EmptyState с объяснением и осмысленным CTA (только если действие реально доступно).
* Мутации — кнопка в состоянии `loading`, повторные клики игнорируются; успех/ошибка — тост.
* Списки — «Показать ещё» с отображением «Загружено N из M».

### 5.5. Фильтры истории

Поиск (номер/направление/уровень), чекбоксы направлений, селект уровня, сегменты статуса,
слайдер минимального балла 0–10 с шагом 0.5. Активные фильтры считаются, «Сбросить» сбрасывает
все сразу. Фильтрация клиентская по загруженным данным; «Показать ещё» догружает страницы API.
Пустой результат фильтра отличается от пустой истории.

## 6. Анатомия экранов

Далее: назначение, расположение блоков и ключевые тексты. Все кнопки — глагольные.

### 6.1. `/login` — вход

* **Слева (520px, поверхность):** бренд, H1 «Вход в аккаунт», подзаголовок, форма
  (Email, Пароль с кнопкой «Показать/скрыть», кнопка «Войти»), ссылка «Зарегистрироваться»,
  копирайт.
* **Справа (≥1024px):** поясняющая панель на `surface-2`: «Как проходит подготовка», 3 шага,
  блок «Работает без ключа API» (офлайн-движок — честное описание).
* Состояния: ошибка входа — алерт над формой; отправка — кнопка в loading; гостевой маршрут,
  авторизованного редиректит на `/`.

### 6.2. `/register` — регистрация

Та же раскладка. Поля: имя (плейсхолдер «Алексей Смирнов»), email, пароль (подсказка «Минимум
6 символов»), повтор пароля. Клиентская валидация: имя ≥ 2, формат email, пароль ≥ 6, совпадение.
Кнопка «Создать аккаунт».

### 6.3. `/` — дашборд

* H1 «Здравствуйте, {Имя}», описание, кнопки «История» и «Новое собеседование».
* Баннер незавершённой сессии (если есть) с кнопкой «Продолжить».
* Табы: **Обзор | Сессии (N) | Темы**.
* **Обзор:** подпись «Показатели за всё время»; 4 KPI-карточки (Всего сессий, Средний балл,
  Отвечено вопросов, Серия занятий); сетка 8/4: график «Динамика баллов» с переключателем
  периода (30 дней / 90 дней / всё время) и панель «Темы для повторения»; ниже — «Последние
  сессии» (таблица, 5 строк) и «Следующие шаги» (3 производных подсказки со ссылками).
* **Сессии:** таблица недавних сессий + ссылка «Открыть историю».
* **Темы:** слабые темы, сильные темы, средний балл по сложности.
* Пустое состояние: карточка «Начните с первого собеседования» + пустые блоки с объяснениями.
* Данные: `GET /api/analytics/overview`; KPI — за всё время, период влияет только на график
  (честно подписано).

### 6.4 `/interview/new` — новая сессия

* H1 «Новая сессия». Сетка 8/4.
* Слева: «Направление» (радио-карточки из `/api/meta`), «Уровень» (сегменты),

## 8. Доступность (WCAG 2.1 AA)

| Критерий | Реализация |
|---|---|
| 1.4.3 Контраст текста | Основной текст `fg` ≈ 16:1; `fg-2` ≈ 7.5:1; `fg-3` ≈ 4.6–4.9:1 (минимум 4.5:1). Проверено для светлой и тёмной тем. |
| 1.4.11 Контраст нетекстовых элементов | Границы контролов ≥ 3:1 к фону; фокус-кольцо контрастно обоим темам. |
| 1.4.1 Использование цвета | Статусы дублируются текстом в бейджах; пробелы/успехи — иконка + текст. |
| 2.1.1 Клавиатура | Все действия доступны с клавиатуры: формы, табы, сегменты, поиск, дропдауны, модалки. |
| 2.1.2 Нет ловушек фокуса | Модалки закрываются по Esc, дропдауны — по Esc и клику вне. |
| 2.4.7 Видимый фокус | Глобальный `:focus-visible`: 2px accent + offset 2px для всех интерактивных элементов. |
| 2.5.5 / 2.5.8 Цель нажатия | Кнопки и иконки-кнопки 40×40px; строки списков ≥ 40px; чекбоксы с областью 40px. |
| 3.3.1/3.3.2 Ошибки и подсказки | Ошибки полей связаны текстом под полем, `role="alert"`; подсказки — статический текст. |
| 4.1.2 Имя, роль, значение | Нативные элементы; ARIA только там, где нужно (`tablist/tab`, `combobox/listbox`, `radiogroup`, `progressbar`, `aria-current`, `aria-label` для иконок). |
| 1.3.1 Структура | Заголовки H1→H2, `table` с `th scope="col"`, `nav aria-label`, списки `ul/ol`. |
| 3.1.1 Язык | `<html lang="ru">`. |
| 1.4.4 Масштабирование | Все размеры в px/rem без фиксированных высот контента; при 200% зума layout не ломается (кроме ожидаемого скролла). |
| 2.3.1/2.3.3 Движение | Нет автовоспроизведения; анимации короткие и функциональные. |

Известные ограничения: экранные дикторские проверки не проводились (нет браузерного окружения в
песочнице); панель-дропдауны не реализуют полный focus-trap (закрываются по Esc/вне, фокус
возвращается к триггеру после клика). Это отмечено как следующий шаг.

## 9. Контент и микрокопирайтинг

* Заголовки — существительными («Новая сессия», «История сессий»), кнопки — глаголами
  («Начать собеседование», «Проверить решение», «Сохранить изменения»).
* Ошибки: что произошло + что сделать («Не удалось загрузить данные. Проверьте соединение с
  сервером»). Никаких «Oops!» и технических кодов без перевода.
* Плейсхолдеры реалистичные: «Алексей Смирнов», `alexey.smirnov@example.com`,
  «SQL и базы данных», «3 года коммерческой разработки на Python: FastAPI, PostgreSQL, Docker…».
* Не обещаем несуществующего: нет «демо-аккаунта», нет «забыли пароль», нет квот и тарифов;
  статус ИИ и задержка — реальные значения из API/измерения.
* Пустые состояния объясняют, какие действия приведут к данным, и не показывают выдуманные
  примеры вроде «сессия #12 с баллом 7.1», если их нет в API.
