# 05. Стратегия и организация тестирования

**Проект:** «Интеллектуальный тренажёр для подготовки к собеседованиям»
**Версия документа:** 1.0
**Связанные документы:** [Техническое задание](01-ТЗ.md), [Архитектура](02-Архитектура.md), [Сценарии](03-Сценарии.md), [API-контракт](API.md)

## 1. Цели и принципы тестирования

Цель тестирования — подтвердить, что система выполняет требования
[01-ТЗ.md](01-ТЗ.md) и соответствует контракту [API.md](API.md) в двух режимах
ИИ: `offline` (детерминированный, используется в автотестах и демонстрации) и
`live` (внешняя модель, проверяется выборочно и вручную).

Принципы:

1. **Детерминированность автотестов.** Все автоматические тесты выполняются в
   офлайн-режиме: `AI_API_KEY` пуст или `AI_PROVIDER=offline`, поэтому оценка
   воспроизводима.
2. **Изоляция данных.** Каждый тестовый запуск работает с временной SQLite-БД
   (переменная `DATABASE_URL` задаётся до импорта приложения); рабочая
   `backend/data/app.db` не затрагивается.
3. **Проверка контракта, а не реализации.** Интеграционные тесты обращаются к
   API через `TestClient` и проверяют коды состояния, поля и бизнес-правила из
   [API.md](API.md), не полагаясь на внутренние структуры.
4. **Трассировка требований.** Каждый тест-кейс связан с FR/NFR, а критерии
   приёмки AC-1…AC-13 из [ТЗ](01-ТЗ.md) имеют явный способ проверки.
5. **Быстрый цикл.** Весь набор должен проходить за минуты, без сети и без
   внешних сервисов.

## 3. Окружение тестирования

Особенности окружения описаны в [DEV_SETUP.md](DEV_SETUP.md); для тестов
существенны три правила:

1. **Python-интерпретатор проекта** — `.venv\Scripts\python.exe`.
2. **`PYTHONPATH` указывает на `tools\pyfix`** — обход ограничения ACL песочницы
   (иначе создание временных каталогов падает с `PermissionError`).
3. **Временная БД.** `conftest.py` выставляет `DATABASE_URL` на
   `<repo>/.tmp/pytest/test_app.db` **до** импорта `app.main`, поэтому `engine`
   создаётся уже для тестовой базы; при старте прогона старые файлы БД удаляются,
   а перед каждым тестом схема пересоздаётся (`drop_all` + `create_all`).
4. **Принудительный офлайн-режим.** В `conftest.py` задаются
   `AI_PROVIDER=offline`, пустой `AI_API_KEY` и тестовый `SECRET_KEY`; тесты
   не обращаются к сети и не зависят от ключей.
5. **Фикстуры.** `client` (TestClient с запущенным lifespan), `db_session`
   (прямой доступ к SQLAlchemy), `user`/`user_headers`,
   `second_user`/`second_headers` (проверка изоляции), `make_user` (фабрика
   пользователей), а также помощники `create_interview`, `submit_answer`,
   `register_user`, `auth_headers`.

```powershell
$ws = "C:\Users\MILLER\Downloads\HH7d"
$env:PYTHONPATH = "$ws\tools\pyfix"
Set-Location "$ws\backend"
& "$ws\.venv\Scripts\python.exe" -m pytest -q
```

Сквозная проверка без сервера:

```powershell
& "$ws\.venv\Scripts\python.exe" scripts\smoke_check.py
```

Конфигурация pytest — `backend/pytest.ini`: `testpaths = tests`,
маска файлов `test_*.py`, подавление предупреждений `DeprecationWarning`,
`PendingDeprecationWarning`, `RuntimeWarning`.

## 4. Тест-кейсы

Обозначения: **P** — предусловие, **Ш** — шаги, **О** — ожидаемый результат,
**Т** — связанные требования.

> **Результаты контрольного прогона версии 1.0.** `python -m pytest -q` из
> `backend/` — **207 тестов пройдено** (включая параметризованные; 117 тестовых
> функций в 11 модулях), 0 падений. `python scripts/smoke_check.py` —
> **26 проверок пройдено, 0 провалено**, код возврата 0 (режим `offline`,
> изолированная БД).

## 6. Критерии выхода

Тестирование считается завершённым, если:

1. `python -m pytest -q` из `backend/` проходит полностью (кроме явно
   пропущенных тестов с обоснованием в коде);
2. `python scripts/smoke_check.py` завершается с кодом 0: все проверки
   `[OK]`, ни одной `[FAIL]`;
3. выполнены все критерии приёмки AC-1…AC-13 из [01-ТЗ.md](01-ТЗ.md);
4. не осталось открытых дефектов уровня «блокирующий»/«критический»;
5. сборка фронтенда (`npm run build`) завершается без ошибок TypeScript, и
   интерфейс проходит ручной чек-лист;
6. дефекты уровня «незначительный» зафиксированы и не влияют на основные
   сценарии.
